# BFTA Brand Kit

Single source of truth for every Bitcoin for the Arts logo, lockup, social
asset, and source file. Everything in this folder ships to production at
`https://bitcoinforthearts.org/brand-kit/...` — direct links work both
internally (in code) and externally (in email signatures, partner sites,
Google Docs, etc.).

## Naming convention

```
<family>-<background>-<accent>[-alt].png

family      = main | square | inline
background  = the dominant color of the canvas (cream, black, orange, green)
accent      = the contrasting wordmark/script color
-alt        = inverse colorway of the same background
              (e.g. green = orange BFT + black A;
                    green-alt = black BFT + orange A)
```

Why "alt" instead of "-1/-2": the version numbers from the agency don't
have inherent meaning. "-alt" tells you immediately that it's the inverse
colorway of its sibling, and stays meaningful regardless of upload order.

## Picking the right asset

| Use case | Pick this |
|---|---|
| Website nav / footer / popup | `square-bugs/square-cream-orange-alt.png` |
| Website main hero (transparent on cream) | `derived/main-transparent-light.png` |
| Favicon / iPhone home-screen icon | `square-bugs/square-cream-orange-alt.png` (regenerated by `scripts/build-favicons.mjs`) |
| Open Graph share preview | `social/BFTA-social-post-cream-orange-2160.png` (also generated) |
| Profile avatar (IG / X / FB / LinkedIn) | `social/BFTA-social-profile-inline-*.png` family |
| Pre-cropped circle avatar (transparent corners) | `social/BFTA-social-circle-*.png` family |
| Cover banner (X / LinkedIn / Facebook) | `social/BFTA-social-banner-*.png` family |
| Print / merch / partner co-branding | Pull from `source-files/*.ai` for vector |
| External brand co-marketing | Hand them the PDF in `guidelines/` |
| Sponsor sheet / business card / flyer "scan to donate" | `qr-codes/donate.png` |
| Sponsor deck or event flyer "scan to learn more" | `qr-codes/art-zap-weekend.png` |
| Generic business card / signature scan-code | `qr-codes/home.png` |
| Recruitment poster / table tent | `qr-codes/volunteer.png` |
| Artist outreach / grants table | `qr-codes/grants.png` |
| "Follow us on X / Nostr" CTAs | `qr-codes/x.png`, `qr-codes/nostr.png` |

### QR code usage rules

- The 1024px file is the print master. Use it for anything that will be
  scaled up beyond a business card. The `-512.png` is for web/social only.
- **Don't recolor** the QR or invert it. Most phone scanners assume dark
  modules on a light background — flipping it can break scannability.
- **Don't shrink below ~0.75 inch / 2 cm** when printed. Smaller than that
  and most camera apps can't lock focus reliably.
- **Don't crop** the white margin (the "quiet zone"). It's not decorative —
  it's part of how scanners detect the code's edges.
- Pair the QR with the destination URL printed in plain text underneath.
  Scanners are good but plain-text fallback covers older phones and
  accessibility needs.
- All seven codes use error-correction level **H** (~30% redundancy), which
  is why we can put the BFTA bug logo in the center without breaking them.
  This has been verified by re-decoding each PNG end-to-end after generation.

## How derived assets get regenerated

```bash
node scripts/build-favicons.mjs                # all favicon + app icon sizes
node scripts/build-transparent-main-lockup.mjs # /derived/*.png
node scripts/build-social-lockups.mjs          # /public/social/* (~140 files)
node scripts/build-brand-qr-codes.mjs          # /qr-codes/*.png (14 files: 7 URLs × 2 sizes)
```

Each script reads from this folder and writes either back into `derived/`
or into `public/social/`. None of the source files in `main-lockups/`,
`square-bugs/`, `inline-bugs/`, `source-files/`, or `social-icons/` are
auto-generated — those came from the agency or were uploaded by humans.

## Old URLs

Every URL that previously lived at `bitcoinforthearts.org/<filename>.png`
or `bitcoinforthearts.org/resources/logos/...` now 308-permanent-redirects
to its new home in this folder. Definitions live in `next.config.ts`.

If anyone reports a stale link returning 404, add a redirect entry there;
don't move the file back.
